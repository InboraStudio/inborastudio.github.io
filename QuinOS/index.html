The 5-Year Evolutionary Journey

From a 32-bit educational prototype to an advanced 64-bit multi-core desktop operating system. Research and implementation led by Dr Chamyoung (Alok) at Inbora Studio (2021 – 2026).

2021 • Year 1

XuNet OS Genesis (32-Bit Bare-Metal Prototype)

Research commenced with XuNet OS, an educational 32-bit x86 operating system. Implemented real mode to protected mode switching, 8259 PIC interrupt remapping, FAT12 floppy filesystem, basic VESA VBE 640×480 graphics, and custom keyboard scancode decoders. Established fundamental low-level systems knowledge.

16-to-32-bit Switch 8259 PIC FAT12 VESA VBE XuNet OS 32-Bit
2022 • Year 2

The 64-Bit Architecture Pivot (Quin OS 1)

Re-architected from the ground up for x86_64 Long Mode. Formulated Multiboot 1 and Multiboot 2 compliance in boot.asm, 4-level PML4 paging tables with 2 MB huge identity mapping, Higher-Half Direct Map (HHDM at 0xFFFF800000000000), 256-gate IDT, serial COM1 logging, and initial Local APIC discovery.

x86_64 Long Mode PML4 4-Level Paging HHDM Multiboot2 256-Gate IDT
2023 • Year 3

Kernel Core & Multiprocessing Infrastructure

Engineered the Physical Memory Manager (order 0–10 Buddy Allocator, 4 KB to 4 MB frames), Virtual Memory Manager with Copy-on-Write sys_fork() and huge page splitting, ACPI MADT parsing, AP INIT-SIPI-SIPI wake-up trampoline at 0x8000, preemptive priority round-robin scheduler with 100 Hz PIT quantum, and Virtual Filesystem (VFS) mount table.

Buddy Allocator (Orders 0-10) CoW Fork ACPI MADT SMP PIT 100 Hz VFS Slab Pool
2024 • Year 4

Desktop Compositor & Graphics Breakthrough

Created the double-buffered Quin Display Server (QDS), coverage-based integer anti-aliased geometry engine (QAA), floating Quin Window Manager (QWM) with 32 concurrent windows and macOS-style traffic light chrome, QuinUI widget toolkit, VirtIO-GPU 2D modern PCI driver supporting 2560×1440 resolution, and persistent Ext2 read/write on VirtIO-Blk.

QDS Double Buffer QAA Acrylic Blur QWM Floating WM VirtIO-GPU 2560x1440 Ext2 Read/Write
2025 • Year 5

Bare-Metal Network Stack, Audio & Userspace Groundwork

Authored an RFC 793 Transmission Control Protocol (TCP) from scratch in pure C with 3-way handshake, sliding window rings, and Jacobson/Karels RTO estimation. Integrated DHCP, DNS, HTTP client with gzip decoding, SNTP clock sync, AC97 DMA 16-bit stereo audio, SHA-256 user authentication, and initial Ring-3 userspace ELF loading linked against cross-compiled musl libc 1.2.4.

RFC 793 TCP Engine AC97 DMA Audio musl libc 1.2.4 SNTP Clock Sync SysV AMD64 ABI

kernel/arch/x86_64/boot.asm

1. Bootstrapping & 64-Bit Long Mode Transition

Quin OS boots via GRUB2 adhering to both Multiboot 1 (0x1BADB002) and Multiboot 2 (0xE85250D6) standards. The transition from 32-bit protected mode into 64-bit Long Mode is orchestrated in boot.asm:

  • Verifies CPUID and Long Mode capability via cpuid function 0x80000001 (bit 29 of EDX).
  • Constructs an initial identity page table mapping the first 1 GB using 2 MB huge pages (Present, Writable, Huge flag 0x83).
  • Maps PML4 index 256 to establish the Higher-Half Direct Map (HHDM) starting at virtual address 0xFFFF800000000000.
  • Enables PAE (Physical Address Extension) in CR4.PAE, activates Long Mode in IA32_EFER.LME, and engages paging in CR0.PG.
  • Executes a far jump into the 64-bit Code Segment selector (0x08) and branches to kernel_main(magic, mboot_addr) in kernel/src/main.c.
boot.asm — Paging & Far Jump 
; Load PML4 physical base address into CR3
mov eax, boot_pml4
mov cr3, eax

; Enable PAE (bit 5 of CR4)
mov eax, cr4
or  eax, 1 << 5
mov cr4, eax

; Enable Long Mode in EFER MSR (0xC0000080, bit 8)
mov ecx, 0xC0000080
rdmsr
or  eax, 1 << 8
wrmsr

; Enable Paging (bit 31) and Protection (bit 0) in CR0
mov eax, cr0
or  eax, (1 << 31) | (1 << 0)
mov cr0, eax

; Far jump into 64-bit code segment
jmp 0x08:long_mode_entry
kernel/src/pmm.c & kernel/src/vmm.c

2. Memory Architecture: Buddy Allocator & 4-Level Paging

Memory is managed through a layered physical/virtual architecture:

Physical Memory Manager (PMM): Implements a Buddy Allocator managing orders 0 through 10 (4 KB to 4 MB contiguous blocks). Frame state is recorded in a bitmap, and free blocks are tracked via embedded free_block_t descriptors guarded by magic value 0x12345678U. Frame sharing across Copy-on-Write forks is tracked using a 32-bit reference counter array (s_refcounts).

Virtual Memory Manager (VMM): Coordinates the 4-level AMD64 paging hierarchy (PML4, PDPT, PD, PT). Higher-Half Direct Map (HHDM) begins at 0xFFFF800000000000, mapping all physical RAM. The lower half (0x0000000000000000 to 0x00007FFFFFFFFFFF) is dedicated to isolated userspace processes.

pmm.c — Buddy Allocator Order Merging 
/* Calculate buddy frame index for order */
static inline uint64_t get_buddy_frame(uint64_t frame_idx, uint8_t order) {
    return frame_idx ^ (1ULL << order);
}

/* Free a block of physical frames and coalesce buddies */
void pmm_free_order(physaddr_t addr, uint8_t order) {
    spinlock_acquire(&s_pmm_lock);
    uint64_t frame = addr_to_frame(addr);

    while (order < PMM_MAX_ORDER) {
        uint64_t buddy = get_buddy_frame(frame, order);
        if (!is_buddy_free(buddy, order)) break;

        remove_from_free_list(buddy, order);
        frame = (frame < buddy) ? frame : buddy;
        order++;
    }

    add_to_free_list(frame, order);
    spinlock_release(&s_pmm_lock);
}
kernel/src/scheduler.c & kernel/arch/x86_64/switch.asm

3. Preemptive SMP Scheduler & Atomic Context Switching

Multi-core processing is coordinated through ACPI MADT enumeration and per-CPU state structures (g_per_cpu[SMP_MAX_CPUS]). Each CPU core operates three priority run-queues (High, Normal, Low) and an idle thread. Slicing is triggered by PIT Channel 0 programmed in Mode 2 (Rate Generator, command 0x34) at 100 Hz (10 ms quantum), supplemented by per-core Local APIC 1 kHz timers.

Atomic Lock Release in switch_context (BUG-080): To prevent sibling cores from stealing a thread whose saved stack pointer (prev->rsp) is not yet written, the run-queue spinlock release is performed directly in assembly inside switch_context after RSP is safely moved to the incoming thread's stack.

switch.asm — Atomic Lock Release Context Switch 
switch_context:
    ; RDI = prev thread, RSI = next thread, RDX = &runq_lock
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15

    mov [rdi + 8], rsp   ; Store updated RSP into prev->rsp
    mov rsp, [rsi + 8]   ; Load next thread's saved RSP

    ; ATOMIC: Release spinlock ONLY after we are off prev's stack!
    mov dword [rdx], 0

    pop r15
    pop r14
    pop r13
    pop r12
    pop rbp
    pop rbx
    ret
kernel/arch/x86_64/syscall.asm & kernel/src/aslr.c

4. System Calls & Kernel Security Hardening

System calls enter via the SYSCALL instruction. Model-Specific Registers (MSRs) configure the entry point:

  • IA32_LSTAR points to syscall_entry.
  • IA32_FMASK clears IF, DF, and the Alignment Check (AC) bit. Clearing AC provides hardware-level mitigation for CVE-2012-0217 (Intel SYSRET vulnerability).
  • syscall_entry executes swapgs, preserves all 16 registers in a 128-byte syscall_frame_t, and validates user pointers against canonical higher-half boundaries.
  • ASLR: aslr.c implements a 32-bit maximal-length Galois LFSR with polynomial $x^{32} + x^{22} + x^2 + x + 1$ (tap mask 0xB4BCD35CUL) seeded from rdtsc and PIT ticks to randomize user ELF base addresses with 2 MB alignment.
gui/qds/ & gui/qaa/ & gui/qwm/

5. Graphics Engine & Compositor Architecture

The graphical desktop comprises three integrated subsystems:

  • QDS (Quin Display Server): Double-buffered presentation engine maintaining back and front buffers. Tracks dirty bounding damage rectangles (dmg_x, dmg_y, dmg_x2, dmg_y2) to minimize PCI transfer overhead.
  • QAA (Quin Anti-Aliased Engine): Pure-integer coverage rasterizer for smooth rounded rectangles, circles, sub-pixel fonts, and frosted-glass acrylic blur.
  • QWM (Quin Window Manager): Floating compositor managing up to 32 windows, macOS-style traffic light buttons with hover interpolation, 7-pixel hit-tested edge resizing, live edge snapping, and centered floating dock with live 100 Hz uptime clock.
drivers/net/tcp.c & drivers/net/ntp.c

6. Bare-Metal RFC 793 TCP Engine & Protocols

Quin OS incorporates a complete TCP/IP stack implemented without external networking libraries:

  • RFC 793 TCP: Full state machine (SYN, ESTABLISHED, FIN_WAIT, TIME_WAIT). Sliding window send/receive rings, MSS and window-scale negotiation, Jacobson/Karels dynamic RTO estimation (200 ms to 15 s), fast retransmit on three duplicate ACKs.
  • Network Protocols: Ethernet framing, ARP cache with aging, IPv4 header checksumming, ICMP echo, UDP datagrams, DHCP client, DNS resolver, and RFC 4330 SNTP client (ntp.c) correcting RTC drift against global time servers.
  • HTTP Client: HTTP/1.1 client with in-tree gzip decompression via miniz and TLS encryption via ported mbedtls.
kernel/src/ext2.c & kernel/src/vfs.c

7. Storage Architecture & Ext2 Filesystem

The Virtual File System presents a unified mount table (16 entries) supporting USTAR initrd, tmpfs, devfs, procfs, and Ext2. The Ext2 driver (kernel/src/ext2.c) provides full read/write support backed by VirtIO-Blk or AHCI SATA disks.

Hardware Safety Gate: To protect physical host disks from accidental data loss during bare-metal booting, ext2_init() verifies the volume label against EXT2_QUIN_VOLUME_LABEL ("QUINOS_DISK"). Unlabeled drives are strictly rejected from mounting.

drivers/

8. Modern Hardware Driver Subsystem

Drivers are compiled monolithically into the kernel binary, communicating through clean VFS device nodes:

  • VirtIO Suite: VirtIO-GPU (2D resource create, scanout), VirtIO-Net (NIC rings), VirtIO-Blk (ext2 storage), VirtIO-Input (tablet coordinates).
  • Native Storage: AHCI SATA controller with DMA, NVMe PCIe queues, legacy ATA PIO mode.
  • USB Stack: USB 3.0 xHCI controller, USB 1.1 UHCI controller, USB HID keyboard/mouse, USB Mass Storage (MSC).
  • Audio: Intel 82801AA AC97 audio codec with DMA buffer playback (NABMBAR) and PC Speaker via PIT Channel 2.
userspace/ & musl-1.2.4/

9. Ring-3 Userspace & musl libc Integration

Userspace applications execute in Ring-3 as standard ELF64 binaries linked against musl libc 1.2.4. The kernel ELF loader (elf.c) maps PT_LOAD segments into per-process PML4 page tables, configures a 16 MB stack, initializes the System V AMD64 ABI stack with argc, argv, envp, and auxv, and transfers control via sysretq or iretq.

10. Ported Engines, Gaming & Media

Through its POSIX syscall interface and musl libc runtime, Quin OS 2 runs a wide array of sophisticated ported software:

  • Web Browser: Litehtml box-model layout engine with QuickJS-ng ES2020 JavaScript engine.
  • Video Player: MPEG-1 video and MP2 audio decoding via pl_mpeg synchronized with AC97 audio.
  • Physics Sandbox: Chipmunk2D rigid-body dynamics simulation with gravity and collision geometry.
  • Gaming & Emulation: Stockfish chess engine, DOOM, Quake 1, Nintendo Entertainment System (NES), Game Boy, and Sega Genesis emulators.
  • Productivity: SQLite 3 database, Lua 5.4 interpreter, Redis in-memory cache, and Tiny C Compiler (TCC).

#include <stdio.h>

int main(void) {
    printf("Compiled from bare metal inside Quin OS 2!\n");
    return 0;
}

root@quin:~# tcc -o hello.elf hello.c
root@quin:~# ./hello.elf
